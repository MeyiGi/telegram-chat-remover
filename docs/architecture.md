# Архитектура

Сейчас проект работает одним процессом. Каждая автоматизация живёт в своём модуле, а Telegram, Groq, Notion и будущие внешние сервисы подключаются через отдельные адаптеры. Если какой-то сценарий позже потребует собственного развёртывания, его можно будет вынести без переноса правил остальных сценариев.

```text
Telegram → архив сообщений и медиа → сценарии → внешние сервисы
                    │                  │        ├─ Notion
                    │                  │        ├─ Groq
                    │                  │        └─ Google Drive: резервная копия медиа
                    └─ SQLite: состояние заданий и результаты
```

## Где что находится

```text
main.py, auth.py                короткие точки входа для старых команд
couplebot/
  __main__.py                   запуск через python -m couplebot
  cli/                          команды запуска и авторизации
  config.py                     настройки из .env, читаются при запуске
  app.py                        сборка приложения и запуск сценариев
  features/
    cleanup/                    правила удаления и Telegram-обработчики
    diary/                      ежедневный дневник и расписание
    media_backup/               повторяемая загрузка медиа и учёт состояния
    stats/                      статистика и команда /stats
  integrations/
    telegram/                   авторизация, сообщения, медиа и экспорт
    http.py                     общий HTTP-клиент для JSON
    groq.py                     запросы к Groq
    notion.py                   страницы и блоки Notion
    google_drive.py             загрузка файлов в Google Drive
  storage/
    archive.py                  SQLite, медиа и JSON-экспорт
tests/                          проверки с поддельными внешними сервисами
docs/                           архитектура и шаблон нового сценария
```

`app.py` соединяет компоненты. Сценарий получает нужные зависимости при создании; он не читает `.env`, не импортирует `app.py` и не обращается к чужому сценарию напрямую. Форматы API принадлежат `integrations/`, схема БД и миграции — `storage/`.

Основной запуск — `python -m couplebot`, авторизация — `python -m couplebot.cli.auth`. Пакет лежит в корне репозитория и не требует установки; `python main.py` и `python auth.py` пока сохранены как тонкие оболочки для старых команд. Тесты и рабочий код импортируют модули только из `couplebot`.

## Действующие сценарии

| Сценарий | Запуск | Локальные данные | Внешнее действие | Защита от повтора |
| --- | --- | --- | --- | --- |
| Архив | перед удалением, дневником и статистикой | сообщения и медиа в `data/` | нет | `(chat_id, message_id)` |
| Удаление | новое сообщение, прочтение, онлайн и таймер | состояние ожидания и журнал | удаление в Telegram | проверка архива и состояния чата |
| Статистика | `/stats` или `/statistics` | JSON из архива SQLite | ответ в Telegram | только чтение |
| Дневник | 05:00 по местному времени, за вчера | архив и `diary_runs` | Groq и страница Notion | дата и метка в Notion |
| Резервная копия медиа | вместе с синхронизацией архива | путь и ID Drive-файла в SQLite | загрузка в Google Drive | `appProperties` и `drive_media_uploads` |

Резервное копирование включается через `GOOGLE_DRIVE_ENABLED=1`. Одноразовая авторизация запускается командой `python -m couplebot.cli.google_drive_auth`; локальные файлы архива загружаются в папку из `GOOGLE_DRIVE_FOLDER_NAME`. Модуль использует OAuth scope `drive.file`, отдельную папку приложения и возобновляемую загрузку больших файлов. Перед удалением сообщений облачная копия медиа должна завершиться успешно.

## Как расширять

Желания, памятные даты, договорённости, свидания, подарки, списки просмотра, вопросы, резервирование медиа и версии досье должны быть отдельными сценариями. Для каждого сначала определяем событие запуска и устойчивый ключ обработки. Для сообщения это `(chat_id, message_id, feature)`, для ежедневной работы — `(feature, local_date)`. Так повтор после ошибки не создаст копию записи.

Извлечённый факт хранит ссылку на исходное сообщение. Для изменяемых сведений, например досье, новая версия добавляется с датой и источником; старая не исчезает. Notion и облачный диск служат местом отображения и хранения файлов, но локальное состояние задания определяет, завершена ли обработка.

Если внешний сервис не даёт надёжных событий, сценарий периодически сравнивает снимки состояния. Проверка подписок Instagram должна иметь собственный адаптер и журнал снимков; она не зависит от удаления Telegram-чата.

## Надёжность

- Сначала сохраняем данные, затем выполняем действие, которое нельзя отменить. Проверка медиа и атомарный JSON-экспорт остаются обязательными перед удалением.
- Для внешней записи сохраняем состояние задания и ID созданного объекта. Ошибки одного сценария не останавливают остальные.
- Секреты хранятся в `.env`; текст личной переписки не попадает в обычные логи. AI-сервису передаётся только необходимый для задачи фрагмент.
- Новые сценарии, создающие внешние записи, получают отдельный переключатель в настройках.

Чтобы добавить сценарий, начните с [шаблона](new-feature.md), создайте папку `couplebot/features/<name>/`, добавьте адаптер или методы хранения при необходимости, зарегистрируйте сценарий в `app.py` и напишите проверки с поддельными API. Не добавляйте новый большой блок в `main.py`.
